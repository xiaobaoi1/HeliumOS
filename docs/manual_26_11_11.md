# 第一部分：总览

## 1.1 分层架构


|架构|
|---|
| USER: shell / wm / desktop / term / kilo / MUI |
| USER: libc（原生）+ posix shim（POSIX 兼容）|
| 边界：int 0x80，寄存器传参，独立句柄空间|
| KERNEL: proc / mem / fs / ipc / pty / sig / net|
| KERNEL: device_ops + 各驱动|
|硬件|


## 1.2 内存布局（x86 32 位，3GB/1GB 分割）

| 范围 | 用途 | 定义处 |
|---|---|---|
| `0x00000000 - 0x08000000` | 内核恒等映射（128MB，PSE 4MB 页） | `start.asm` |
| `0x08000000 - 0x10000000` | `kmap` 窗口（128MB） | `kmap.h` |
| `0x10000000 - 0x40000000` | 未映射 | — |
| `0x40000000 - 0x50000000` | 用户 ELF 加载区 | `vmm.h` `USER_SPACE_START` |
| `0x50000000 - 0x60000000` | 用户堆（`brk`） | `task.h` `heap_base` |
| `0x60000000 - 0x70000000` | 用户 `mmap` 区 | `syscall.c` `MMAP_BASE` |
| `0x7FF00000 - 0x7FFFE000` | 用户栈 VMA（128KB，lazy） | `task.c` |
| `0xB0000000` | Framebuffer 用户映射基址 | `syscall.c` `FB_USER_BASE` |

## 1.3 句柄空间一览（**互不混用**）

| 空间 | 上限 | 分配函数 | 类型 |
|---|---|---|---|
| `fs_handle` | 32 | `fs_alloc_handle` | `fd_t` |
| `ipc_handle` | 8 | `ipc_handle_alloc` | `int` |
| `pty_handle` | 16 | `handle_alloc` | `int` |
| `dev_handle` | 8 | `dev_alloc_handle` | `dev_t` |
| `proc_handle` | 8 | `proc_handle_alloc` | `proc_handle_t` |
| `sock_handle` | 8 | `sock_handle_alloc` | `int` |

**核心约束**：同一整数在不同空间里语义不同。`sys_write(stream, buf, n)` 的 `stream` 是标准流编号（0/1/2），不是任何句柄空间。

# 第二部分：KERNEL

## 2.1 启动链

**职责**：GRUB → 分页 → `kmain` → 子系统初始化 → 首个用户进程。

**关键文件**：`start.asm`、`kmain.c`

**数据流**：

```
GRUB (Multiboot2)
  ├─ EAX = magic, EBX = mb_info 物理地址
  ↓ _start
  ├─ 拷贝 mb_info 到 BSS（分页前，物理直访）
  ├─ 清 page_directory
  ├─ PDE 0..31 = 恒等映射 0..128MB（0x83 = P|W|PS）
  ├─ CR4.PSE=1，CR3=page_directory，CR0.PG=1
  ├─ ESP = stack_top
  ↓ kmain(magic, addr)
```

`kmain` 初始化顺序有硬依赖：

```
dev_init → irq_init → serial_init → screen_init → tty_init
  → ipc_init → input_init → pty_init
  → pmm_init → heap_init → vma_init → shm_init → file_map_init
  → gdt_init → fpu_init → tss_init → vmm_init → kmap_init
  → idt_init → rtc_init → acpi_init → fb_init
  → volume_init → fs_init
  → keyboard_init → serial_register_dev
  → pci_init → graphic_init → audio_init → ata_init → net_init
  → e1000_init（失败回退 rtl8139_init）
  → net_proto_init → net_sock_init → tcp_init
  → 扫描所有 ATA 设备 MBR，挂载第一个 FAT32 = SYS
  → font_init → mouse_init
  → create_init_task (PID 1) → create_idle_task
  → scheduler_start
  （/INIT 随后启动 WM → DESKTOP → DHCP；SHELL 由桌面 Terminal 启动）
```

**不变量**：
- `heap_init` 必须在 `pmm_init` 之后（slab 从 pmm 拿页）
- `idt_init` 打开 PIT（1000Hz）之前 `irq_init` 必须先清注册表
- `sizeof(struct task) > 4096` 会 panic（`kmain` 末尾检查）

## 2.2 内存管理链

### 2.2.1 PMM（物理页，位图）

**文件**：`memory/pmm.c`
**数据**：`bitmap[1GB/4KB/8] = 32KB`，`MAX_PHYS_MEM = 1GB`

**入口**：`pmm_init(mb_addr)` 解析 Multiboot2 mmap，标记：
1. `type==1` 的可用区清位
2. 强制保留 0..1MB
3. 保留 `_kernel_start.._kernel_end`
4. 保留位图自身
5. 保留 **`0x08000000..0x10000000`**（kmap 窗口物理地址不可恒等访问）

**关键函数**：
- `pmm_alloc_page()` — 线性扫第一个空位，O(n)
- `pmm_alloc_pages(n)` — 连续 n 页，仍是线性扫
- `pmm_free_page(phys)`

**坑**：`pmm_alloc_pages` 里 `if (n == 1) return pmm_alloc_page();` 是特例优化，但 n=0 返回 0（不 panic）。

### 2.2.2 VMM（虚拟内存，页表）

**文件**：`memory/vmm.c`、`include/vmm.h`

**PDE 分布**：
- PDE 0..255（0..1GB）：内核区，进程 pgd 从主 `page_directory` 拷贝
- PDE 256..1023（1GB..4GB）：用户区，进程 pgd 独立
- **PDE 1023**：递归映射（`0xFFC00000` 可访问页表）

**关键函数**：
- `vmm_create_process_page_directory()` — 拷内核 256 项，清用户区
- `vmm_map_user_page(pgd, virt, phys, flags)` — **virt 必须 ≥ `USER_SPACE_START`**，否则打印警告并返回
- `vmm_unmap_user_page` / `vmm_get_phys`
- `vmm_free_process_address_space` — 遍历用户 PDE，释放所有页表页和物理页

**不变量**：内核区页表**共享**（进程 pgd 拷贝的是 PDE 值，不是页表内容）。所以 `kmap` 修改的内核页表对**所有进程**可见。

### 2.2.3 Heap（slab 分配器）

**文件**：`memory/heap.c`

**9 个大小类**：8/16/32/64/128/256/512/1024/2048 字节

**大对象路径**（`> 2048`）：
```
kmalloc(size) → pmm_alloc_pages → 页头 large_header{magic1,magic2,pages,size}
                → 返回 phys + sizeof(large_header)
kfree(ptr) → 检查页头双 magic → pmm_free_pages(page, pages)
```

**坑**：
- `kfree` 不检测 double-free（slab 路径会把同一对象挂两次到 `free_list`）
- `LARGE_MAGIC` 用 `0xB16B00B5 / 0xDEADBEEF` 双 magic，碰撞概率极低但非零
- `LARGE_MAX_SIZE = 4MB`，超过返回 NULL（防恶意请求耗尽物理内存）

### 2.2.4 kmap（临时映射窗口）

**文件**：`kernel/kmap.c`
**窗口**：`0x08000000..0x10000000`（**128MB**，注释里写 64MB 是错的）

**用途**：把物理地址映射到内核虚拟，访问超出恒等映射范围的物理内存（FB、AHCI ABAR、ACPI 表等）。

**坑**：
- 位图 `kmap_bitmap[KMAP_PAGES/8]` 跟踪窗口页，**找连续空闲页是 O(n)**
- `kmap_free` 需要精确的 `len`，传大了释放不该释放的页
- **`pmm_alloc_pages` 不会返回 kmap 窗口内物理地址**（`pmm_init` 保留），所以 `kfree` 里 `phys + 16` 的恒等映射假设安全——**但这是隐式契约，不是硬保证**

### 2.2.5 SHM（共享内存对象）

**文件**：`kernel/shm.c`、`include/shm.h`
**上限**：`SHM_MAX_OBJECTS = 64`，`SHM_MAX_PAGES = 4096`（16MB/对象）

**结构**：
```c
struct shm {
    char     name[SHM_NAME_MAX];  // 32
    uint32_t num_pages;
    uint32_t refcount;            // VMA 引用数
    uint32_t *pages;              // 页数组（按需分配）
    uint8_t  used, unlinked;
};
```

**生命周期**：
- `sys_shm_open(name, size, flags)` — 存在则返回 idx，否则创建
- 映射：`sys_mmap(MAP_SHARED, shm_idx, offset)` → `vma_insert(..., VMA_TYPE_MMAP, shm, ...)` → `shm_ref`
- 取消映射：`sys_munmap` → `shm_unref`（页由 VMA 生命周期决定，不是 shm）
- `sys_shm_unlink(name)` — 标 `unlinked=1`，`refcount==0` 时销毁

**坑**：
- **`shm_destroy` 释放页数组和每页**，但在 `unlinked=0` 且 `refcount=0` 时**不销毁**——这是泄漏源（上一轮 P0 #4 的根因）
- `shm_create` 里 `pmm_alloc_pages(arr_pages)` 分配页数组，`memset` 越界问题（`num_pages > 1024` 时 `num_pages*4 > 4096`）在早期版本存在，当前 `SHM_MAX_PAGES = 4096` → 页数组最大 16KB → 4 页，`pmm_alloc_pages(4)` 能分配，`memset(bytes)` 也是正确的 `num_pages*4`，**当前无越界**

### 2.2.6 VMA（虚拟地址区间）

**文件**：`kernel/vma.c`
**类型**：`HEAP / STACK / MMAP / ELF / PIPE / FILE`

**链表**：按 `start` 升序，插入、查找、区间移除（可拆分）都是链表操作。

**关键约束**：
- `vma_node_bad()` 检查指针范围 `[0x00100000, 0x10000000)` 且 `start < end < 0xC0000000`——**防损坏节点导致内核 panic**
- 拆分 VMA 时右段共享 `shm` / `filemap` 引用计数（`shm_ref` / `file_map_ref`）
- `vma_insert` 检测重叠，返回 `EEXIST`

### 2.2.7 file_map（文件页缓存）

**文件**：`kernel/file_map.c`
**上限**：`FILE_MAP_MAX = 32`

**用途**：`mmap(MAP_FILE)` 共享文件内容。以 `(vol, first_cluster)` 为 key 缓存 `file_mapping`。

**数据流**：
```
sys_mmap(MAP_FILE, fd, offset)
  → file_map_get(vol, first_cluster, file_size)
  → vma_insert(..., VMA_TYPE_FILE, NULL, 0)
  → v->filemap = fm; v->filemap_offset = offset / 4096

缺页时：
  handle_page_fault
    → file_map_get_page(fm, page_idx)  [分配物理页 + fat32_read_file]
    → vmm_map_user_page
```

**坑**：
- **`file_map_get_page` 边界**：如果 `page_idx * 4096 >= file_size`，`read_sz` 会变成负数（uint32 下溢），越界写。**上一轮 P0 #3 已指出**。
- `sys_mmap(MAP_FILE)` 静默接受非页对齐 `offset`（`offset / 4096` 截断）——语义错误，应 `EINVAL`

## 2.3 进程链

### 2.3.1 Task 结构（前 6 字段强耦合）

```c
struct task {
    uint32_t pid;              // offset 0
    uint32_t state;            // offset 4
    uint32_t time_slice;       // offset 8
    uint32_t *pgd;             // offset 12
    uint32_t kernel_stack_phys;// offset 16
    uint32_t kernel_esp;       // offset 20  ← switch_to 直接读写
    ...
};
```

**`start.asm` 的 `switch_to` 用 `[eax+12]`、`[eax+20]`**——改前 6 字段顺序必须同步 `start.asm`。

### 2.3.2 Task 创建链

**文件**：`process/task.c` `task_create()`

**资源分配顺序**（任何一步失败回滚）：
```
pmm_alloc_page() → PCB (4KB)
pmm_alloc_page() → 内核栈 (4KB)
pmm_alloc_page() → 用户栈低页
pmm_alloc_page() → 用户栈高页
vmm_map_user_page(pgd, 0x7FFFC000, stack_low, P|W|U)
vmm_map_user_page(pgd, 0x7FFFD000, stack_high, P|W|U)
vma_insert(STACK, 0x7FF00000..0x7FFFE000, lazy)
proc_register
构造用户栈（envp 字符串 / argv 字符串 / envp 数组 / argv 数组 / argc）
setup_slot × 3（stdin/stdout/stderr）
构造内核栈（iret 帧 + pusha + 段寄存器 + enter_user_mode + callee-saved）
kernel_esp = sp
enqueue_task(ready_queue)
```

**内核栈布局**（从高到低）：
```
ss=0x23
user_sp（指向 argc）
eflags=0x202
cs=0x1B
eip=entry_point
int_no=0, err_code=0
8 × pusha
gs/fs/es/ds = 0x23 × 4
enter_user_mode（返回地址）
ebp/ebx/esi/edi = 0 × 4  ← kernel_esp 指这里
```

### 2.3.3 调度链

**文件**：`process/scheduler.c`

```
PIT (IRQ0, 1000Hz)
  → irq_handler
    → proc_reap_graveyard()    [回收 zombie]
    → sleep_tick()             [递减 SLEEPING，检查 WAITING_CHILD 超时]
    → current->time_slice--
    → time_slice==0 → schedule()
```

`schedule()`：
```
if (current->in_schedule) return;     // 防嵌套
if (time_slice>0 && state==RUNNING) return;
current->in_schedule = 1;
if (state==RUNNING) { state=READY; enqueue; }
for (;;) {
    next = dequeue(ready_queue);
    if (next) {
        if (next == current) { state=RUNNING; return; }
        set_current(next);
        switch_to(current, next);
        current = get_current();
        current->in_schedule = 0;
        return;
    }
    sti; hlt; cli;   // 无进程可跑，等时钟
}
```

**不变量**：
- `in_schedule` 防止"中断里调 schedule"和"外层 schedule"嵌套消费 ready 队列
- `switch_to` 保存 `prev->kernel_esp`，恢复 `next->kernel_esp`，切 CR3，更新 TSS.esp0
- 首次调度（`prev == NULL`）通过 `enter_user_mode` 跳到用户态

### 2.3.4 进程退出/回收链（graveyard）

```
sys_exit → task_exit
  → fs_release_all / dev_release_all / ipc_release_all / pty_release_all
  → 释放 proc_handle / net_sock_handle
  → input_release_keyboard / display_set_owner(0)（如果是 owner）
  → remove from ready_queue
  → zombie = 1, state = ZOMBIE
  → enqueue blocked_list
  → wake_up_waiters
  → proc_unref(self)
       refcount--；若归零 && zombie：
           如果 t == current → graveyard
           否则 → proc_free_pcb(t)
  → schedule()   [current 是 ZOMBIE，不会被 dequeue]
```

**关键**：`task_exit` 不释放自己的 `pgd` / `kernel_stack` / PCB。当前进程如果在 `task_exit` 里释放自己的栈，`switch_to` 切走后栈已经没了，**崩溃**。所以走 graveyard，下次时钟 tick 的 `proc_reap_graveyard` 回收。

### 2.3.5 spawn 链

```
sys_spawn(path, argv, params_user)
  → strncpy_from_user(path)
  → copy_from_user(spawn_params, min(size, sizeof))
  → 检查权限（child_class/caps 需要 CAP_SPAWN_SYS）
  → 拷贝 argv/envp 到内核堆
  → vmm_create_process_page_directory()
  → resolve_path → fat32_volume
  → load_elf_from_disk
  → task_create（含 setup_slot 处理 redir_fd/pipe/pty）
  → proc_handle_alloc(child, PROC_ALL)
  → 回填 out_pid
  → 返回 handle
```

**坑**：
- 旧版 `spawn_params`（`size < sizeof`）用 `memset(&p, 0, sizeof(p))` 后 `copy_from_user` 只覆盖 `size` 字节，**未覆盖字段是 0 不是 -1**——`redir_in = 0` 会绑定到父进程 fs handle 0，不是 INHERIT。**上一轮 P1 #5 已指出**。
- `setup_slot` 是宽容策略：任何失败都 fallback 到 `IO_SLOT_DEFAULT`

## 2.4 中断与异常链

**文件**：`kernel/idt.c`、`kernel/isr.c`、`kernel/irq.c`、`boot/start.asm`

### 2.4.1 异常（int 0..31）

```
ISR_NOERR/ISR_ERR → isr_common_stub
  → pusha, push ds/es/fs/gs, 段寄存器切 0x10
  → push esp; call isr_handler
  → 异常处理的三种路径：
    1. page fault (int 14) → handle_page_fault（lazy 分配）
    2. 用户态异常 → signal_from_exception → SIGSEGV/SIGFPE/SIGILL
    3. 内核态异常 → extable_lookup(eip)
                   命中 → regs->eip = fixup, 返回
                   未命中 → panic_regs
  → iret
```

### 2.4.2 IRQ（int 32..47）

```
irq_common_stub → irq_handler
  → EOI（>= 40 额外发从 PIC EOI）
  → int 32 (PIT)：proc_reap_graveyard + sleep_tick + schedule
  → int 33..47：irq_dispatch(irq-32) → g_slots[irq].fn
  → 返回前 signal_deliver_pending
  → iret
```

**不变量**：
- `irq_init` 在 `kmain` 最开头，清空 `g_slots`
- `pic_unmask_irq` 在 `irq_register` 里调用——**注册即启用**
- IRQ0（PIT）不走注册表，硬编码在 `irq_handler` 里

### 2.4.3 系统调用（int 0x80）

```
isr80 → syscall_common_stub → pusha + 段寄存器
  → push esp; call isr_syscall_handler
    → syscall_handler(regs)
      → switch (regs->eax) { case SYS_*: ... }
      → regs->eax = ret
      → signal_deliver_pending(regs, cur)
  → pop / iret
```

**不变量**：`syscall_handler` 进入时 IF=0（int 0x80 中断门自动关中断），所以进程链表、VMA 链表遍历安全。

## 2.5 文件系统链

### 2.5.1 卷与路径

**文件**：`fs/volume.c`、`fs/path.c`

**卷符系统**：`SYS:/path`，`SYS` 是第一个挂载的 FAT32。`volume_lookup(name)` 查表。

**`resolve_path(input, out)`**：
```
if (split_volume_prefix(input, vol_name, &inner) == 0):
    // 绝对路径 "NAME:/path"
    v = volume_lookup(vol_name)
    out->path = "/" + inner
else:
    // 相对路径，基于 cwd
    拼接 cwd_path + "/" + input
normalize_path(out->path)
```

**`normalize_path`**：原地处理 `.` / `..` / 多重斜杠，不跨卷根。

### 2.5.2 fs 门面

**文件**：`fs/fs.c`

`struct fs_handle` 有 `fs_type` 字段，所有操作 switch 分发：
```c
int fs_read(fd, buf, n) {
    h = fs_get(fd);
    switch (h->fs_type) {
        case VOL_FS_FAT32: return fat32_read_file(...);
        default: return ENOSYS;
    }
}
```

**当前只有 FAT32**，没有 VFS。

### 2.5.3 FAT32

**文件**：`drivers/fat32.c`（2000+ 行）

**关键实现**：
- **FAT 扇区单槽缓存**（`fat_cache_lba / fat_cache[512]`）——局部性好时够用
- **LFN**：`find_entry_in_dir` 累积 LFN 项，用 `short_name_checksum` 校验防止孤立 LFN 污染
- **簇分配**：`last_alloc_hint` 避免每次从头扫
- **写扩展**：`fat32_write_file` 按需分配簇链，`update_dirent` 更新目录项
- **读加速**：跨簇连续读（探测 `next == probe + 1`，最多 64 簇）

**坑**：
- LFN 跨扇区删除有边界问题（`idx - lfn_count < 0` 时不标记）——少见但存在
- **195 字符文件名上限**（要求所有 LFN + 短名项同扇区），比 FAT 规范窄 60 字符

### 2.5.4 ELF 加载

**文件**：`kernel/elf_loader.c`

```
load_elf_from_disk(vol, path, pgd)
  → fat32_open_file
  → 读 ELF header，检查 magic
  → for each PT_LOAD:
      if (filesz > memsz) return 0
      if (vaddr + memsz 溢出) return 0
      if (vaddr + memsz > USER_SPACE_END) return 0
      if (vaddr < USER_SPACE_START) continue    // 跳过内核段
      分配物理页 → vmm_map_user_page
      逐扇区读文件内容 → memcpy 到物理页
      .bss 清零
  → return header.entry
```

**不变量**：`ph.vaddr >= USER_SPACE_START` 的段才加载。这意味着内核 ELF 段（如果有）被忽略——**对用户程序正确，但对 `IDLE`/`WM`（CLASS_KERNEL）也一视同仁**。

## 2.7 IPC 链

### 2.7.1 Pipe

**文件**：`kernel/ipc.c`
**上限**：`IPC_MAX_PIPES = 16`，`PIPE_BUF_SIZE = 4096`

**核心结构**：

## 2.8 PTY 链

**文件**：`kernel/pty.c`
**上限**：`PTY_MAX_PAIRS = 8`，`PTY_MAX_HANDLES = 16`，`PTY_BUF_SIZE = 4096`，`PTY_LINE_MAX = 256`

### 2.8.1 数据流

```
term（master） ←to_master← [行规程 or raw] ←to_slave← shell（slave）
       →to_slave→                          →to_master→
```

### 2.8.2 行规程（cooked 模式）

`line_discipline(p, c)`：
- **ESC 过滤**：丢弃 `\x1b[...` 序列（方向键 / Delete 等）
- **控制字符过滤**：只保留 `\n \r \b \t ^C ^D ^U`
- **^D EOF**：`line_len > 0` 提交当前行，否则 `eof_pending = 1`
- **^C SIGINT**：清行 + 回显 `^C\n` + 给 `fg_pid` 投递 SIGINT + 唤醒
- **^U 清行**：`\r` + N 空格 + `\r`
- **退格**：`\b \b`
- **回车**：提交整行 + `\n` 到 slave + 回显 `\n`
- **普通字符**：存 `line_buf` + 回显

### 2.8.3 raw 模式

直接逐字节写入 `to_slave`，不处理行规程。`term_set_raw(1)` 切到 raw。

### 2.8.4 阻塞队列

- `wait_master`：master 读空时阻塞
- `wait_slave`：slave 读空时阻塞
- `wait_slave_write`：slave 写满时阻塞（**单槽，多写者会覆盖**——见上一轮 P2）

**坑**：`pty_read_master` **没有 slave 已关的 EOF 检测**。slave handle 全关闭后，`to_master` 空，master 的 `pty_read` 一直阻塞——term 无法知道 shell 退出（上一轮 P0 #2）。

## 2.9 信号链

**文件**：`kernel/signal.c`、`include/signal.h`

### 2.9.1 投递（syscall 返回前）

```
signal_deliver_pending(regs, cur)
  循环 32 次：
    pending = cur->pending_signals & ~cur->blocked_signals
    if (pending == 0) return
    选最低位 sig
    cur->pending_signals &= ~(1 << sig)
    if (sig == SIGKILL) → task_terminate + schedule
    if (a->handler == SIG_IGN) continue
    if (a->handler == SIG_DFL):
        default_is_ignore(sig) → continue
        else → task_terminate + schedule
    else → deliver_user_handler
```

### 2.9.2 用户 handler 投递

```
deliver_user_handler
  new_esp = (user_esp - sizeof(sigframe)) & ~3
  写 sigframe{ret_addr=restorer, sig, saved_*, saved_eip, saved_user_esp, saved_mask}
  regs->eip = a->handler
  regs->user_esp = new_esp
  cur->blocked_signals |= a->mask | (1 << sig)
```

### 2.9.3 sigreturn

```
sys_sigreturn(regs)
  frame_esp = regs->user_esp - 4
  读 sigframe
  恢复所有寄存器
  cur->blocked_signals = f.saved_mask
```

**不变量**：`user_esp - 4` 是对的——`ret` 从 `__sigreturn_trampoline` 弹出返回地址后 esp 前进 4，`int 0x80` 保存的 `user_esp` 是 `frame_esp + 4`。

## 2.10 网络链

### 2.10.1 协议栈

```
net_deliver(frame)
  → net_proto_rx
    → net_eth_rx
        ARP → net_arp_rx
        IP  → net_ip_rx
              ICMP → net_icmp_rx
              UDP  → net_udp_rx
              TCP  → tcp_input
```

### 2.10.2 ARP

- 缓存：`g_arp[8]`，`{ip, mac, valid}`
- 学习：任何 IP 包的 `src_ip + src_mac` 都写入缓存
- 未命中：发 ARP 请求，返回 -1（**上层立即失败，不重试**）

### 2.10.3 IPv4

- 接收：检查 version/ihl/total_len，接受 `dst == g_ip` 或广播
- 发送：loopback（`dst == g_ip`）走 `net_ip_rx`；否则 ARP 解析，未命中发 ARP 请求并返回 -1
- **`g_ip_valid == 0` 时 `src_ip = 0`**，DHCP 阶段依赖广播

### 2.10.4 UDP

- 端口 → socket：`udp_socket_by_port(dst_port)`
- 无 socket：静默丢弃
- 队列：`rx_queue[8]`，满了丢弃

### 2.10.5 TCP（简化状态机）

**状态**：`CLOSED / LISTEN / SYN_SENT / SYN_RCVD / ESTABLISHED / FIN_WAIT_1 / FIN_WAIT_2 / CLOSE_WAIT / LAST_ACK`

**关键路径**：
- **被动打开**：LISTEN → 收到 SYN → 分配 socket → SYN_RCVD → 回 SYN-ACK
- **ESTABLISHED 数据**：`seq == rcv_nxt` 才入 `rx_buf`，乱序丢弃
- **接收窗口**：`rx_buf` 满时回 0 窗口 ACK
- **重传**：`txq[8]`，`rto_ms` 指数退避，8 次放弃
- **FIN**：`tcp_close` 入队 FIN，`txq` 重传覆盖丢包

**已知 bug**（上一轮 P0 #1）：零窗口后 `tcp_recv` 取走数据不主动发窗口更新，对端 persist timer 探测 `seq == rcv_nxt - 1` 被丢弃 → 连接挂死。

### 2.10.6 socket 封装

**文件**：`kernel/net_sock.c`

- `sys_socket(domain, type, proto)` — 分配 `udp_socket` + `sock_handle`
- `sys_bind` — 检查端口冲突
- `sys_sendto / sys_recvfrom` — UDP / TCP 分流
- `sys_connect / sys_listen / sys_accept` — TCP 主动/被动打开
- **accept 是轮询**：`sys_connect` 最多 3 秒（300 × `ksleep(10)`）

# 第三部分：USER

## 3.1 crt0 与 libc 初始化链

**文件**：`user/crt0.S`

```asm
_start:
    xor %ebp, %ebp
    mov (%esp), %eax             # argc
    lea 4(%esp), %edx            # argv
    lea 8(%esp, %eax, 4), %ecx   # envp = esp + 8 + 4*argc
    push %ecx; push %edx; push %eax
    push %ecx
    call __libc_init_environ    # environ = heap 拷贝
    add $4, %esp
    pop %eax; pop %edx; pop %ecx
    push %edx; push %eax
    call main
    add $8, %esp
    mov %eax, %ebx
    mov $1, %eax                 # SYS_EXIT
    int $0x80
    hlt
```

**布局验证**：`task_create` 构造的栈 `user_sp` 指向 argc，`argv[0]` 紧跟其后，`envp[0]` 在 `argv + 4*argc + 4`。**和 crt0 的 `lea 8(%esp, %eax, 4)` 匹配**。

### 3.3.2 合成链（shm 协议）

**文件**：`shm_layout.h`

```
offset 0:  uint64_t counter          [每次发布 ++]
offset 8:  uint32_t cur_x0..cur_y1   [term 累积中]
offset 24: uint32_t pub_x0..pub_y1   [已发布]
offset 40: uint32_t pixels[w*h]
```

**协议**：
- `term`：`mark_dirty` 更新 `cur`；批末若 `pub` 空，`pub = cur`，`counter++`，`cur = EMPTY`
- `WM`：`counter` 变化 → 读 `pub` → `blit` → `pub = EMPTY`

**不变量**：`cur` 一直累积，`pub` 空时才发布——**不丢更新**。

**坑**：`counter` 是 `uint64_t`，i386 上非原子读（上一轮新 P1）。

### 3.3.3 窗口列表推送

`push_window_list()` → 遍历 `g_wins`，打包 `wm_event + n × wm_window_entry` → `pipe_write(dock->event_w)`。

**坑**：**完全无 pipe 满保护**（上一轮 P0 #3）。dock 进程卡住时 WM 挂死。

### 3.3.4 输入路由

```
route_mouse_move(mx, my)
  popup 命中？→ popup
  dock 命中？→ dock
  最高 z 的 NORMAL？→ w 其中 z 最大的
  wallpaper
  → update_mouse_entered（ENTER/LEAVE）
  → send_event(MOUSE_MOVE)
```

`handle_mouse_press`：
- popup 命中：转发 MOUSE_DOWN
- dock：转发
- NORMAL：
  - 三按钮区（close/max/min）
  - tab 区（tab_hit_test → close/activate/new）
  - 标题栏（拖动）
  - 客户区（转发 MOUSE_DOWN）

### 3.3.5 拖动链

```
MOUSE_DOWN → handle_mouse_press → drag_win = hit, drag_dx/dy
MOUSE_MOVE（drag_win 非空）：
    mouse_restore
    计算新旧 bbox
    g_dragging = drag_win; g_no_present = 1
    redraw_region（旧区域 - 交集）
    redraw_region（新区域 - 交集）
```

### 3.5.2 主循环

```
for (;;) {
    while (pipe_avail(ev_rd) >= sizeof(ev)) {
        读事件
        KEY：如果 scrolled → scroll_end；否则 ime_key 或 pty_write
        RESIZE：term_resize
        NEW_TAB：term_spawn_tab
        CLOSE_REQUEST：发 WM_REQ_DESTROY 并返回
        MOUSE_*：滚动条交互
        WHEEL：scroll_by
    }

    int av = pty_avail(g_master);
    if (av < 0) { ... 关闭窗口并返回 ... }   // 只在 master 无效时触发
    if (av > 0) {
        ime_restore(); cursor_restore();
        读 pty 数据 → process_byte
        term_present(); cursor_draw(); ime_draw();
    }

    // 发布脏区（cur → pub）
    if (pub 空 && cur 非空) { pub = cur; counter++; cur = EMPTY }

    sleep_ms(1);
}
```

**坑**：`av == 0` 时（master 有效但无数据），如果 slave 已关闭（shell 退出），**循环永远 sleep 1ms**——没有 EOF 检测（上一轮 P0 #2）。

### 3.5.3 ANSI 解析

`process_byte(c)` 状态机：
- `ansi_state == 0`：普通字节，UTF-8 解析后 `render_cp`
- `ansi_state == 1`：收到 `\x1b`，等 `[` 或 `O` 或其他
- `ansi_state == 2`：参数累积，`final` 字符触发 `ansi_handle_final`

**支持**：
- `m`（SGR 颜色）
- `J`（清屏，只支持 2/3）
- `H`/`f`（光标定位）
- `K`（擦行，0/1/2）
- `A`/`B`/`C`/`D`（光标移动）
- `h`/`l`（只支持 `?25` 光标可见性）

**不支持**：`\x1b[6n`（光标位置查询）——`kilo` 的 `getCursorPosition` 会死锁（但通常走 `ioctl` 分支，不触发）。

### 3.5.4 滚动条与回滚

- `g_hist[32 行]` 环形缓冲，`scroll()` 时把顶行 push 进历史
- `g_scrolled`：当前显示历史视图
- `g_live`：实时屏幕副本（滚回时恢复）
- `term_compose_view(v)`：从历史行 + live 行合成当前显示

### 3.5.5 IME

- `g_ime_on`：Ctrl+Space 切换
- `g_ime_buf`：拼音缓冲
- `ime_lookup_pinyin(g_ime_buf)` → `ime_word{cand[5]}`
- 数字键 1-9 选择，Space/Enter 提交首选，Esc 取消

**坑**：IME 状态在 term 和 desktop 各有一份，不共享。

### 3.5.6 resize

`term_resize(new_w, new_h)`：
1. 分配 `new_live` / `new_hist`
2. 旧内容拷贝到新尺寸（保留左上部分）
3. 创建新 shm，`mmap`
4. `WM_REQ_RESIZE{old_shm, new_shm, new_w, new_h}` 发给 WM
5. `munmap(old_shm)` → **没有 `shm_unlink(old_shm)`**（泄漏，上一轮 P0 #4）
6. 更新 `g_*`
7. `pty_set_winsize`
8. `pty_write(master, "\x1bW")` 通知子进程 resize（`kilo` 识别为 `RESIZE_KEY`）

**坑**：`new_shm` 名用 `g_my_ev_name[8] - '0'`（只能区分 term 0-9，上一轮 P0 #1）。

## 3.6 SHELL 链

**文件**：`shell.c`

### 3.6.1 初始化

```
term_set_raw(1)             [shell 自己做行编辑]
sigaction(SIGINT, SIG_IGN)
打印欢迎
```

### 3.6.2 读一行（read_line）

**自己实现行编辑**（不依赖 pty 行规程）：
- 打印绿色 prompt
- 逐字节读 stdin
- ESC `[...` 序列：上/下（历史）、左/右、Home/End、Delete、PageUp/PageDown
- `^C` 返回 0
- `^D` 空行时返回 -1（EOF）
- `^U` 清行
- 退格：删光标前字符，`line_redraw`
- 可打印字符：插入光标处，`line_redraw` 或直接写

`line_redraw(buf, len, cursor)`：`\r` + prompt + buf + `\x1b[K` + 回退 N 个 `\x1b[D`。

### 3.6.3 词法

`tokenize(cmd, argv, max)`：
- 按空格/制表符分割
- **保留引号**（留给 `expand_word`）
- 引号内的空格不分割

### 3.6.4 展开

`expand_argv(in, argc, out, out_max)` 对每个 token 调 `expand_word`：
- `'...'`：字面量，不展开
- `"..."`：`$VAR` 展开，`*?` 不展开
- 其他：`$VAR` 展开，`*?` 标记为 glob
- glob 匹配走 `glob_expand`（`fs_opendir` + `glob_match`），无匹配保留原 pattern
- 展开结果存放在 `g_expand_buf`（静态 16KB 环形）

### 3.6.5 执行

```
builtin（exit/help/ls/cd/pwd/clear/touch/mkdir/rmdir/rm/mv/cp/date/halt/reboot/ps/uname/ifconfig/dns/kill/sink）
否则 run_pipeline(argv)
```

`run_pipeline`：
1. `split_by_pipe` 分段
2. `parse_redirect` 摘除 `< file` 和 `> file`
3. 创建 `nseg-1` 个 pipe
4. 逐段 `spawn`，传 `in_pipe` / `out_pipe` / `in_fd` / `out_fd`
5. shell 侧 `ipc_close` / `fs_close` 所有 pipe 和 fd
6. `wait` 所有子进程
7. `process_close`

**坑**：`term_set_raw(0)` 切 cooked 给子进程，`wait` 后 `term_set_raw(1)` 恢复。这是 pty raw 是**全局**标志的直接后果——shell 想同时拥有"行编辑（raw）"和"子进程 cooked"，只能来回切。

## 3.8 跨层协议汇总

### 3.8.1 shm_layout

```c
#define SHM_HDR_SIZE  40
struct shm_hdr {
    volatile uint64_t counter;
    volatile uint32_t cur_x0..cur_y1;
    volatile uint32_t pub_x0..pub_y1;
};
static inline uint32_t shm_total_size(int w, int h);
```

### 3.8.2 wm_proto

| 结构 | 用途 |
|---|---|
| `wm_event` | WM → client（type/code/x/y/extra） |
| `wm_window_entry` | 窗口列表（id/minimized/title） |
| `wm_request` | client → WM 创建窗口 |
| `wm_destroy_request` | client → WM 销毁 |
| `wm_resize_request` | client → WM resize |
| `wm_action_request` | dock → WM 窗口动作 |
| `wm_set_cursor_request` | client → WM 光标 |
| `wm_set_alpha_request` | client → WM 透明度 |

### 3.8.3 spawn_params

```c
struct spawn_params {
    uint32_t size;          // 必须 sizeof(struct spawn_params)
    int32_t  in_fd, out_fd, err_fd;     // -1=INHERIT, -2=NULL, -3=TTY, >=0=fd
    int32_t  in_pipe, out_pipe, err_pipe;
    int32_t  in_pty, out_pty, err_pty;
    uint32_t flags;
    uint32_t envp;
    uint32_t out_pid;       // [out] 子进程 pid
    uint32_t child_class;   // 0=USER, 1=SERVICE, 2=KERNEL（用户不能创建 KERNEL）
    uint32_t child_caps;
};
```

**坑**：旧版（`size < sizeof`）时未覆盖字段是 0 不是 -1（上一轮 P1 #5）。

### 3.8.4 错误码

`errno.h` 定义 `EPERM(-1)` 到 `EBADF(-25)`，全部负数。`OK = 0`。

# 第五部分：设计哲学速查

| 原则 | 落地 |
|---|---|
| **每子系统独立句柄空间** | fs/ipc/pty/dev/proc/sock 互不混用 |
| **spawn 而非 fork+exec** | `spawn_params` 带 `size` 做版本兼容 |
| **卷符系统** | `SYS:/`，`resolve_path` 处理 cwd 和 `..` |
| **fs.c 门面 + switch** | 不是 VFS，每个 FS 有自己的 `struct fat32_*` |
| **结构体只在必须时用** | `spawn_params` / `fstat_buf` / `rtc_time` 都有固定布局 |
| **原生 > 兼容** | `syscall.h` 的原生接口和 POSIX shim 分离 |
| **改根因不改测试** | `fat32_rename` 同目录原地复用旧项，不删旧建新 |
| **graveyard 延迟回收** | `task_exit` 不释放自己栈，时钟 tick 回收 |
